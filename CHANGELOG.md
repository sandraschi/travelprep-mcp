# Changelog

## Unreleased

- **Migrated REST layer from bare Starlette to FastAPI**, mirroring `arxiv-mcp`'s reference pattern (`mcp-central-docs/standards/FASTMCP_FEATURES.md` §1, `CORS_STANDARD.md`). `mcp.http_app(path="/")` is now mounted at `/mcp` under a real FastAPI app (`build_app()`) instead of using `mcp.custom_route`. Reason: WEBAPP_SOTA_STANDARDS.md §IX is explicit that real Swagger/ReDoc requires FastAPI ("do not manually wire Swagger into a Starlette app") -- this resolves the gap flagged in the previous entry.
  - `/docs`, `/redoc`, `/openapi.json` now real, auto-generated by FastAPI -- live-verified (200s, 6 paths)
  - CORS middleware added (localhost dev server, Tauri webview, tailnet regex) -- was entirely absent before
  - `main()` now runs `uvicorn.run(build_app(), ...)` directly instead of `mcp.run(transport="http", ...)`, avoiding the `run_http_async()` pitfall (silently drops custom middleware/routes)
  - Mounted MCP transport itself live-verified: real JSON-RPC `initialize` handshake through `/mcp` succeeded post-migration
  - `ApiDocsPage.tsx` fixed to match: relative `/docs`/`/redoc` paths (proxied via Vite dev server) so the iframe is same-origin and the dark-theme CSS injection actually works; removed the stale `/api/chat/stream` reference from the quick-ref strip
  - `vite.config.ts` proxy extended: `/skill`, `/docs`, `/redoc`, `/openapi.json` alongside the existing `/api`
- `travelprep-expert` skill — MCP resource (`skill://travelprep-expert/SKILL.md`) + REST (`/api/skills`, `/skill/{name}`), live-verified
- `/api/llm/discover` — Ollama/LM Studio auto-detection (WEBAPP_SOTA_STANDARDS.md §VI "Glom On" pattern), live-tested against real Ollama (qwen3.6:27b)
- Webapp: Dashboard + ToolsHub pages confirmed working against real backend endpoints; ChatPage rewired to the actual fleet reference pattern (chats directly with Ollama, loads skill as base system prompt) instead of a nonexistent backend proxy -- full round trip live-tested
